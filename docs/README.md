# Fish Audit 本机财会审计工作台

打开 [本机工作台](http://127.0.0.1:8000/)。审计人员可以核对同一笔采购的发票、合同及验收资料，也可以核对差旅报销单及具名票据，或按合同核对银行付款回单。在任务台账查看进度，对照原件核实风险与问题，最后填写验收决定。标有「合成演练」的任务可以用来熟悉流程。

要核查一笔款是否达到合同约定的付款条件，选择「合同履约与分期」。提交现行合同及有关验收、质保和回单材料，在「合同履约审查」逐期查看原文、已满足的条件以及缺少的证明。采购与付款、付款回单核对也会列出这组程序。

底稿顶部并列展示签署与生效、交付验收和付款安排。按期点击比例可直接核对合同原页，点击「付款条件」或「实付时点」可跳至该版所据的发现。「未关联回单」表示所交回单尚未对应到该期。代理人签约时，可同时提交委托书，核对签名、授权期限、权限及附加条件。

交付曾不合格时，一并上传原验收单、记录实际措施的整改单和最终复验单。在「交付范围与验收质量」查看对应缺陷的三份记录，点击行旁引文即可核对原页。已识别的第二期验收款会进一步与最终复验日期核对。

验收标准有过变更时，一并上传原合同、补充协议和验收报告。在「终验适用标准」可以并排查看原约定、协议新标准、验收单所引依据和实测值。双方盖章日与终验日各自链接到原页。只适用于将来验收的约定按生效时点核对。若协议还涉及付款前提，底稿会标出待核的条款。

要核对同一合同已付多少，选择「付款回单核对」，提交合同与当次回单。在 B08 的「逐笔复算分期付款」查看本次与前案的累计金额及原页引文。[分期累计超出 150 元的演练](http://127.0.0.1:8000/workpaper/beeaabfec645402facfa497fe0eb7a2a?rev=1&finding=B08-11)

## 使用工作台

1. 选择「新建审计」，填写任务名，选择采购与付款、差旅报销或付款回单核对，并同时上传同一事项的资料。支持电子 PDF、扫描 PDF、Word（DOC、DOCX）、JPEG、PNG、WebP、多页 TIFF 和本机可解码的单张 HEIC/HEIF 照片。每案最多 12 份、60 页，单份 16 MiB，整案 48 MiB。
2. 提交后可关闭或刷新页面。任务页记录分页、逐页解析、建图、执行规则和专家复核。展开「逐份资料进度」可查看每份文件已分页、已提取、已保存视觉复检的页数，并打开已生成的原页图。模型正在读取或复检时会标出当前页。专家响应保存后会显示所属版本。服务若在生成底稿前中断，恢复时会重新核对资料与规则。专家请求完全相符时沿用已保存的响应。
3. 「审计结论」列出建议通过、需要人工校验或建议不通过，并区分已发现的问题、风险和证据不足。展开相符程序也能看到检查依据和引用。点击引用可查看提取值、逐字引文及整张原页。
4. 在「原件与引文」对照页图。电子文档可高亮已定位的原文，扫描件和照片可逐项确认或提出异议。错读用「更正字段」，遗漏用「补录本页字段」，填写逐字引文、取值和理由。重新建图后，展开该字段的「核图时的原件与页图」可回到当时的底稿，下载原件，核对页图与文件摘要。旧版保留原候选及当时的结论。
5. 在一条发现上选择「查看证据路径」，可并排核对执行程序、逐字引文与本项结论。展开某份原件并点击字段可直接定位原页。「知识图谱」还可按实体查询资料、页、观察记录、主体、合同号、票号与金额之间的关系。「执行记录」可查模型版本、调用编号、结构化输出、模型指令及本版本的审计程序源码。旧版底稿可从版本下拉框打开。
6. 核验完成后填写人工决定（通过、退回补件、提交复核）。系统将姓名、时间、意见与指定底稿版本一并归档。同一版本支持一次最终验收。
7. 收到退回意见后，在「补件往来」选择「提交补件」。勾选需沿用的原件，添加新增或替换的资料，可填写补件说明。系统建立独立任务，重新审计本次资料。在「前案退回事项」中，点开程序即可对照前案发现与本次结果，回到各自版本的证据。审计人员随后单独验收补件任务。

8. 选择「提交复核」后，另一位审计人员可在台账「待复核」找到该案。核对转交意见、原版发现与页图，勾选所据发现并填写复核意见。签收为通过或退回时，系统保留初审版并生成复核签收版。复核退回的资料可继续补件。
9. 选择历史版本，在「执行记录」点击「复算本版规则」。系统使用已存图谱和专家建议，从本地发布历史中匹配规则，逐项比较原发现与整案建议。结果会给出匹配提交、源码摘要及可下载的 JSON 记录。若历史源码无法匹配，页面会说明原因。[打开历史底稿的复算入口](http://127.0.0.1:8000/workpaper/cf2467babb6f4e2dba2a4f5d0e9e8a4c?rev=2&view=replay)

## 本机服务

此机已使用用户级 macOS LaunchAgent，监听 `127.0.0.1:8000`，登录后启动并在进程退出后恢复。密钥从 `server/.env` 加载。本机台账支持手填验收姓名。企业工作区支持企业隔离、账户签收及成员权限。参见[企业开通与部署](saas.md)。

```sh
server/.venv/bin/python server/service.py status
server/.venv/bin/python server/service.py restart
server/.venv/bin/python server/service.py stop
server/.venv/bin/python server/service.py install
```

`stop` 卸载本次登录会话中的服务，`install` 重新加载。前台运行时先停止后台实例。同一资料目录只允许运行一个工作进程。

安装和重启命令会等待新进程真正提供网页，再输出可访问的地址。检查覆盖后台任务线程、数据库、首页及首页引用的本地脚本和样式。可用 `GET /api/ready` 检查服务是否就绪。启动超时时，命令返回失败并给出对应实例的日志位置。

SQLite 写锁持续占用时，任务进度页显示后台正在等待写入。后台进程保留当前工作，解除占用后继续保存该次模型响应或提交该次事务。

### 在新环境安装

需要 Python 3.11+（本机使用 3.12）、带中文字体的 LibreOffice 及可联网的 OpenAI 项目。macOS 的 HEIC 通过系统 `sips` 转换。

```sh
python3 -m venv server/.venv
server/.venv/bin/python -m pip install -r server/requirements.txt
server/.venv/bin/python server/main.py
```

在启动前配置 `server/.env`。已有密钥的机器直接使用现有文件。

| 变量 | 用途 |
| --- | --- |
| `OPENAI_API_KEY` | OpenAI 项目密钥，调用仅来自服务端 |
| `OPENAI_MODEL` | 支持图像输入与 Structured Outputs 的识别模型，默认 `gpt-4.1-mini-2025-04-14` |
| `OPENAI_AUDITOR_MODEL` | 专家追加检查模型，默认与识别模型相同 |
| `OPENAI_RECHECK_EVIDENCE` | 默认 `1`，对含候选字段的页图追加一次模型视觉复检。设为 `0` 时保留文字层核验、缺口检查及人工核图 |
| `SOFFICE_BIN`、`AUDIT_CJK_FONT` | 可选的 LibreOffice 命令和中文字体文件 |
| `AUDIT_DATA_DIR`、`PORT` | 本地资料目录与监听端口，默认 `server/data` 与 `8000` |

浏览器把原件传给本机 Python。服务把渲染后的页图发送至 OpenAI Responses API，再把本案相关证据与程序状态交给专家模型。请求设置 `store: false`。供应商端的数据保留还取决于项目设置与适用政策。[图像输入](https://developers.openai.com/api/docs/guides/images-vision) · [结构化输出](https://developers.openai.com/api/docs/guides/structured-outputs) · [OpenAI 数据控制](https://developers.openai.com/api/docs/guides/your-data)

## 证据留存

- `server/data/cases/` 保存原件及模型实际读取的页图，SQLite 保存检查点、资料关系、版本化底稿和验收记录。备份时先停止服务，整体复制数据目录后再启动。
- 「下载底稿及证据包」导出选择的报告版本、原件、页图、独立文字层和导出时的处理日志。新版本另含当次执行的程序源码。涉及跨案重号时，包内还附历史引文所在页图。文件清单含 SHA-256，`report.json` 对应数据库保存的底稿原始字节。
- 运行 `python3 server/verify.py 证据包.zip` 可离线验证文件摘要、底稿版本、来源和关系引用。校验检查包内一致性。独立归档时可另存底稿摘要并保管备份。
- 在安装了对应版本的机器，使用 `server/.venv/bin/python server/verify.py 证据包.zip --rules` 可从本机部署目录复算。验证器从规则入口递归核对项目内静态导入的源码摘要，在独立 Python 进程中使用刚刚核对的文件内容。输出包括复算的发现数及源码文件数。
- 用 `server/.venv/bin/python server/verify.py 证据包.zip --rules-from-git main` 可在本地可信发布历史中匹配规则后复算。另有网页下载的复算记录时，可加 `--replay-receipt 复算记录.json`，会核对当时的提交、底稿版本、规则依赖以及重新计算得到的发现与建议摘要。
- 模型生成的引文可能遗漏或误读。原文定位、规则计算和人工核图分别留痕。资料验真、交易实际发生情况、签章效力、适用税率及正式审计意见仍需审计人员取得相应证据。
