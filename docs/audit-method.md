# 采购与差旅审计的依据与边界

## 本期适用范围

工作台覆盖中国大陆采购付款及差旅报销两种业务。采购规则按同一合同、相同交易双方、人民币元、一次全额验收结算编制。多张发票可逐张复算及查重。满足关联、口径、票号唯一及票内勾稽条件时，可计算本批发票汇总额，交由人工判断分票依据。账簿、银行流水、税务系统和企业审批制度尚未接入。

原始凭证审核的一般制度背景见《中华人民共和国会计法》（2024 年修正）第十四条。下列程序为本项目的采购核对规则。三单齐备、单张发票及全额结算都是该规则集的适用条件。企业实际合同、分期付款和不同业务场景应由审计人员结合授权制度判断。[财政部公布的《中华人民共和国会计法》](https://kjs.mof.gov.cn/zhengcefabu/202408/t20240812_3941615.htm)

采购合同、验收、付款及会计控制对应财政部会计司对采购业务指引的解读第二部分（五）、（七）至（九）。程序将这些内控目标落实为本案可执行的资料核对，并保留条件不满足的记录。[财政部会计司采购业务指引解读](https://kjs.mof.gov.cn/zhengcejiedu/201006/t20100611_322435.htm)

证据分级和追加程序参考注册会计师审计准则第 1301 号（2022 年修订）第三、十、十一、十三及十五条。每个程序均可在底稿中查看具体参考位置、适用范围和版本。[中注协《审计证据》准则正文](https://www.cicpa.org.cn/ztzl1/Professional_standards/xxzztx/zyzz/sjzz/202105/P020240412542695263912.pdf)

## 逐页形成证据

1. 保存上传文件的原始字节并计算 SHA-256。Word 先使用独立 LibreOffice 配置转换。系统会检查 DOCX 正文中的中文字符是否在转换结果中大量丢失。纯图像文档按页保留视觉内容。
2. OpenAI 直接读取逐页图像。程序分配文件和页码，模型返回可见字段、观察值、逐字引文及粗略区域。默认再发起一次视觉检查，逐字段比较候选记录与同一张页图。发现不同或难以辨识时转入人工核图，双次模型读取仍可能有共同误读。界面显示实际送入模型的页图。
3. 对电子文本逐行核对引文、原始取值及语义标签。仅忽略空白并做 Unicode 规范化。缺少可定位的完整行、同页多处同文或字段不匹配时，保留为待核观察。大幅图像底图及不可见文字令整页进入视觉核对。系统另行检查可识别的关键标签行是否被模型遗漏。
4. 每条观察绑定文件摘要、页图摘要、调用记录和本案证据编号。可定位的文本附行号及页图坐标。审计人员可在原件与引文视图确认或提出异议。
5. 图谱只用已匹配原文或经人工确认的字段建立业务关系，按同案、同类型、精确规范化值连接同一实体。来源不同的观察各自留存。相同字段有多种值时，规则输出歧义。金额使用十进制定点计算。
6. 规则执行后，专家代理按案件范围读取实体、带证据编号的关系、程序结果及制度出处。追加程序的触发事实须来自已核记录。比较采购标的时，服务端检查所引资料是否通过同一已核合同编号连接。无效引用留在调用记录中，同时生成证据不足项。报告按规则汇总建议，最终验收另行记录。

文字层匹配和位置框表示对应文字可在资料中找到。它们本身无法证明发票已通过税务查验，也无法证明合同履行。扫描模糊、原文有歧义或不在规则范围时，审计人员可以保留疑问并退回补件。

当同一文件有多种已核单据标题，或不同页分别记载了已核发票标题和不同票号，系统按原页划分单据。每页业务字段只进入该页的检查范围。同页多种标题、合订件中无标题的续页会提示人工核实归属。单一类型跨页文档仍按原文件核对。下载原件保留提交时的完整文件。

## 程序清单

| 编号 | 计算或判断 | 审计人员可以查什么 |
| --- | --- | --- |
| E01 | 查各页辨读情况、已登记字段与原文覆盖程度 | 待核引文、缺口页或原文标签行 |
| P01 | 查单合同、单发票、单验收资料是否齐备 | 已核的标题及整案提交清单 |
| P02、P03 | 沿合同编号及购销双方关系比较 | 各单据中分别记载的编号与双方全称 |
| I01 | 查本案已核发票号码是否重叠 | 同号资料和对应票面。副本、重报须另查 |
| I02 | 将本案已核票号与本工作区已归档底稿中的票号精确匹配 | 当前与历史的票号、原页、归档决定与旧底稿摘要。历史退回或多次提交均需人工判断 |
| M01 | 同票同币种、同单位的不含税合计加税额与价税合计核对到分 | 三个原始数、单位、币种及复算差额 |
| C01、M02 | 核对一次结算条款，再比较同案三单含税金额 | 合同、验收、发票及变更或分批线索 |
| D01、A01 | 检查日期、先后关系、验收合格记载 | 签约、开票、验收日期和验收结论 |
| S01 | 比较采购标的 | 三份资料中的名称，别名和明细差异交人工 |
| X01 | 对分期、调整、保留验收、标的差异等追加程序 | 触发字段、模型所选程序及有效性校验 |

## 差旅报销程序

差旅范围适用于一份申请、实际支出全凭发票报销且索引可逐项核对的场景。T01 检查单据组成，T02 沿申请列明的票号关联随附发票，T03 按相同币种和单位累计凭证并计算与申请金额的差额。申请超出票据合计时列出超额问题，低于票据合计时提示核对个人承担和部分报销。T04 对照费用实际发生日期和行程起止日期，T05 对照具名票据与出差人员。企业差旅标准、补贴、定额与异币报销需另查本单位制度及审批材料。

「建议不通过」表示已执行程序发现可复算问题。「需要人工校验」表示有风险、超出适用范围或证据不足。「建议通过」要求本次全部已执行程序相符。三类建议都保留最终人工验收环节。

## 底稿与重算

一项任务可保存多个底稿版本。旧版建议和调用记录继续可查。人工确认、异议、程序重算及最终决定单独记录。新生成的底稿保存规则说明、适用范围、程序源码快照及其摘要、证据图谱和模型调用。证据包内的 `methods/` 对应生成当版底稿的程序，`journal.json` 留存截至导出时的验收与处理记录。带 `request_format` 的模型调用可以从归档页图、指令、证据输入和输出约束逐字节还原请求并离线核对 SHA-256。校验过程无需联网或 API Key。
