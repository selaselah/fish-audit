# 采购、差旅及付款回单的审计依据与边界

## 本期适用范围

工作台支持中国大陆采购结算、差旅报销及合同与付款回单核对。采购规则按同一合同、相同交易双方、人民币元、一次全额验收结算编制。多张发票可逐张复算及查重。满足关联、口径、票号唯一及票内勾稽条件时，可计算本批发票汇总额，交由人工判断分票依据。银行回单来自上传的原件，银行账务、总账、税务系统和企业审批系统的独立查证需另行完成。

原始凭证审核的一般制度背景见《中华人民共和国会计法》（2024 年修正）第十四条。下列程序为本项目的采购核对规则。三单齐备、单张发票及全额结算都是该规则集的适用条件。企业实际合同、分期付款和不同业务场景应由审计人员结合授权制度判断。[财政部公布的《中华人民共和国会计法》](https://kjs.mof.gov.cn/zhengcefabu/202408/t20240812_3941615.htm)

采购合同、验收、付款及会计控制对应财政部会计司对采购业务指引的解读第二部分（五）、（七）至（九）。程序将这些内控目标落实为本案可执行的资料核对，并保留条件不满足的记录。[财政部会计司采购业务指引解读](https://kjs.mof.gov.cn/zhengcejiedu/201006/t20100611_322435.htm)

证据分级和追加程序参考注册会计师审计准则第 1301 号（2022 年修订）第三、十、十一、十三及十五条。每个程序均可在底稿中查看具体参考位置、适用范围和版本。[中注协《审计证据》准则正文](https://www.cicpa.org.cn/ztzl1/Professional_standards/xxzztx/zyzz/sjzz/202105/P020240412542695263912.pdf)

## 逐页形成证据

1. 保存上传文件的原始字节并计算 SHA-256。Word 先使用独立 LibreOffice 配置转换。系统会检查 DOCX 正文中的中文字符是否在转换结果中大量丢失。纯图像文档按页保留视觉内容。
2. OpenAI 直接读取逐页图像。程序分配文件和页码，模型返回可见字段、观察值、逐字引文及粗略区域。默认再发起一次视觉检查，逐字段比较候选记录与同一张页图。发现不同或难以辨识时转入人工核图，双次模型读取仍可能有共同误读。界面显示实际送入模型的页图。
3. 对电子文本逐行核对引文、原始取值及语义标签。仅忽略空白并做 Unicode 规范化。缺少可定位的完整行、同页多处同文或字段不匹配时，保留为待核观察。大幅图像底图及不可见文字令整页进入视觉核对。系统另行检查可识别的关键标签行是否被模型遗漏。
4. 每条观察绑定文件摘要、页图摘要、调用记录和本案证据编号。可定位的文本附行号及页图坐标。审计人员可在原件与引文视图确认或提出异议。
5. 图谱只用已匹配原文或经人工确认的字段建立业务关系，按同案、同类型、精确规范化值连接同一实体。来源不同的观察各自留存。相同字段有多种值时，规则输出歧义。金额使用十进制定点计算。
6. 规则执行后，专家代理按案件范围读取实体、带证据编号的关系、程序结果及制度出处。追加程序的触发事实须来自已核记录。比较采购标的时，服务端检查所引资料是否通过同一已核合同编号连接。无效引用留在调用记录中，同时生成证据不足项。报告按规则汇总建议，最终验收另行记录。

文字层匹配和位置框表示对应文字可在资料中找到。它们本身无法证明发票已通过税务查验，也无法证明合同履行。扫描模糊、原文有歧义或不在规则范围时，审计人员可以保留疑问并退回补件。

当同一文件有多种已核单据标题，或不同页分别记载了已核发票标题和不同票号，系统按原页划分单据。每页业务字段只进入该页的检查范围。同页多种标题、合订件中无标题的续页会提示人工核实归属。单一类型跨页文档仍按原文件核对。下载原件保留提交时的完整文件。

## 程序清单

| 编号 | 计算或判断 | 审计人员可以查什么 |
| --- | --- | --- |
| E01 | 查各页辨读情况、已登记字段与原文覆盖程度 | 待核引文、缺口页或原文标签行 |
| P01 | 查单合同、单发票、单验收资料是否齐备 | 已核的标题及整案提交清单 |
| P02、P03 | 沿合同编号及购销双方关系比较 | 各单据中分别记载的编号与双方全称 |
| I01 | 查本案已核发票标识是否重复。八位号码须有同页同一张票的代码，二十位号码按全号比较 | 可查看号码及代码的逐字引文。代码缺失、互相冲突或有异议时转人工核验 |
| I02 | 在本企业已签收底稿中检索相同号码，再按完整标识逐笔核对 | 当前与历史的票号、原页、归档决定与旧底稿摘要。历史退回或多次提交均需人工判断 |
| M01 | 同票同币种、同单位的不含税合计加税额与价税合计核对到分 | 三个原始数、单位、币种及复算差额 |
| C01、M02 | 核对一次结算条款，再比较同案三单含税金额 | 合同、验收、发票及变更或分批线索 |
| D01、A01 | 检查日期、先后关系、验收合格记载 | 签约、开票、验收日期和验收结论 |
| S01 | 比较采购标的 | 三份资料中的名称，别名和明细差异交人工 |
| X01 | 对分期、调整、保留验收、标的差异等追加程序 | 触发字段、模型所选程序及有效性校验 |

采购与差旅任务签收为「通过」时，会在写入人工决定的同一事务内重查本企业已签收的同号票据。若另一案刚签收，或已引用前案改由复核人签收，审计员可打开相应版本的原页。初审可保留原版并重算，独立复核可退回补件。重新取得的同票发现由人结合报销、付款和入账资料判断。财会〔2020〕6号第三条第（三）项涉及仅使用外部电子会计凭证报销入账归档时的审签与重复入账防范，该项作为方法参考。[财政部、国家档案局通知](https://www.mof.gov.cn/zcsjtsgb/gfxwj/202003/t20200323_3583778.htm)

采购与差旅的跨案同票发现可展开「核对前案签收依据」。每条引文显示前案版本、人工决定、签收时间和取值方式。对原生文字发票，审计员可以打开票号所在页、对照具体行、下载当时的原件。照片上经过人工确认的票号会关联核图记录。离线校验将票号、单据归属、引文、原件、页图及签收意见逐项与出具时引用的版本核对。较早的底稿会标出当时留存的依据。

在「审计人员验收」或「复核签收决定」展开「签收时的同票检查」，可查看当时实际查验的票号和命中签收版本。缺少可查票号时，回执明确标出范围不足。有可查票号且没有命中时，结果只覆盖本企业当时已签收的任务。回执与原查验版、签收决定一起归档，可定位本案原页和前案签收记录。

## 差旅报销程序

差旅范围适用于一份申请、实际支出全凭发票报销且索引可逐项核对的场景。T01 检查单据组成，T02 沿申请列明的票号关联随附发票，T03 按相同币种和单位累计凭证并计算与申请金额的差额。申请超出票据合计时列出超额问题，低于票据合计时提示核对个人承担和部分报销。T04 对照费用实际发生日期和行程起止日期，T05 对照具名票据与出差人员。企业差旅标准、补贴、定额与异币报销需另查本单位制度及审批材料。

「建议不通过」表示已执行程序发现可复算问题。「需要人工校验」表示有风险、超出适用范围或证据不足。「建议通过」要求本次全部已执行程序相符。三类建议都保留最终人工验收环节。

## 底稿与重算

一项任务可保存多个底稿版本。旧版建议和调用记录继续可查。人工确认、异议、程序重算及最终决定单独记录。新生成的底稿保存规则说明、适用范围、程序源码快照及其摘要、证据图谱和模型调用。证据包内的 `methods/` 对应生成当版底稿的程序，`journal.json` 留存截至导出时的验收与处理记录。带 `request_format` 的模型调用可以从归档页图、指令、证据输入和输出约束逐字节还原请求并离线核对 SHA-256。校验过程无需联网或 API Key。

## 合同与银行付款回单

选择「付款回单核对」，提交一份采购合同及一张同事项银行回单。B01 检查单据归属。B02 对照合同号、采购方与付款户名、供应方与收款户名。B03 使用完整账号比对合同约定账户与回单收款账户，保留前导零。账号有掩码、字段有歧义或主体无法关联时，转人工校验；完整账号不同会提示核实账户变更授权。

B05 核对回单记载的流水号、交易状态和付款日期。B04 在回单记载成功、日期顺序有效、双方及合同号一致、明确单笔全额、同为人民币元的范围内，计算回单付款金额减合同含税总额。每一项算式分别保留两个金额及各自币种、单位的原文。复核人员可在原页内查看模型误读的候选，以及有定位的原文字层并保存更正。

企业实务仍需核实银行实际清算、付款审批及账户变更授权。这里的程序适用范围及阈值由系统声明。采购付款环节的审核方法参考财政部会计司对采购业务内控的解读。[财政部会计司对采购业务的解读](https://kjs.mof.gov.cn/zhengcejiedu/201006/t20100611_322435.htm)

### 跨任务付款核查

| 程序 | 比较条件 | 命中后审计人员要核对什么 |
| --- | --- | --- |
| B06 已签收底稿中的相同流水 | 同一企业、同一已核付款户名、同一完整流水号。保留字母大小写与前导零。已通过、退回补件、提交复核的历史底稿都参与 | 两次提交是否指向同一张回单。对照原签收决定、回单与申请记录，区分补件、副本和重复申请 |
| B07 同合同多笔全额付款线索 | 两案的 E01、B01 至 B05 均相符，合同编号、收付主体、正数人民币元全额相同。前案已经人工通过，回单记载不同的成功流水 | 两笔流水的清算情况、退款、冲正及实际合同履行。两份回单都会进入证据路径 |
| B08 同合同分期付款累计 | 合同有明确分期付款记载。以合同号和收付双方检索同企业已人工通过的付款案，对相同合同原件、完整收款账号、固定人民币元总额和可比的成功回单，按完整流水号去重 | 查看每一笔回单和已签收的历史底稿。累计超出合同总额时查对银行对账单、退款、变更协议。各期是否到期还需验收、履约等资料 |

流水和合同付款各有一组检索记录。出具底稿前，系统会对本企业发生过索引变动的签收版本重新核对归档摘要、付款户名、流水和合同归属。缺行可按签收原版补全，执行记录保留补全项目。索引值与原版冲突或归档摘要不符时暂停出具。初审和独立复核通过前，在写入决定的事务里从待签收底稿重新取数，检查期间新出现的已签收付款线索。

B08 将本案回单与检索时可见的历史回单合计。相同流水的金额和付款日期均相符时只计一次，可以逐一打开副本的金额原文。同流水记载不一致、合同原件不同、出现冲正或变更线索、多个币种或计量单位不明时，暂缓给出累计金额。与合同及双方可关联但取数不齐的已通过底稿也会提示人工核对。一轮最多逐份校验 32 份历史底稿，超过此数时保留命中数和最近 32 份清单，整项转人工。B08 的累计只描述已取得的回单资料。采购合同与付款记录的核对方法参考指引第十三、十五条。[财政部《企业内部控制应用指引第7号——采购业务》](https://kjs.mof.gov.cn/zhengcefabu/201005/P020230421440664863663.pdf)

付款任务只查询本企业已签收的其他任务。B06 和 B07 分别记录检索时点、命中总数及最近签收的至多八份底稿。完整流水待补、主体存在歧义或金额口径不齐时，对应程序提示人工核验。没有命中表示在该时点的可比底稿中没有找到对应记录，企业银行账户的实际收付仍以对账资料为据。

人工点击通过时，系统在写入签收决定的同一事务中重新检查历史。若另一任务刚刚签收并改变了结果，系统保留当前底稿，在「执行记录」中可生成新版。历史引文能打开原签收版本中对应的字段。导出包记录历史签收决定、底稿、所引原件、页图和文字层。离线核验可复查归属、人工决定、金额口径、流水和逐字引文，完整性检索以当时数据库可见的记录为范围。

## 退回事项的后续核验

补件受理时同时锁定前案底稿摘要和签收摘要，沿用资料会核对文件名、大小及 SHA-256。后台对补件任务的实际资料重新分页、读取、建图和执行程序，重新取得发现及建议。审计员能从两案各自的发现打开所用原件和引文。前案的人工核图记录可以在当时的底稿复阅。

「前案退回事项」逐条保留原先有问题、有风险或证据不足的发现，再按同一程序编号列出本次各项状态。遇到规则版本变化会显示两个版本号，未执行的程序也会列明。同号发票或付款流水仍按所选审计范围核对。任务间的补件关系能说明材料提交背景，清算、报销和退款等业务事实仍需取得相应资料。

## 八位票号的逐票关联

传统增值税电子普通发票分别载明十二位发票代码和八位号码，数电发票使用二十位号码。I01 按原页上已核准的代码与八位号码组合，或二十位全号进行比较。代码与号码分别保留逐字引文，前导零参与匹配。本程序也识别原票明列的十位代码。比较结果用于定位待核票据，发票真伪及实际入账次数仍需另行取得依据。[国家税务总局公告 2015 年第 84 号第四条](https://fgk.chinatax.gov.cn/zcfgk/c100012/c5194596/content.html) · [国家税务总局公告 2024 年第 11 号第四条](https://fgk.chinatax.gov.cn/zcfgk/c100012/c5236067/content.html)

报销单逐项列示八位号码时，T02 要求同一行明确列出代码与号码。先将申请列示的项目与附件逐票匹配，才由 T03 汇总人民币元并计算与申请额的差额。对附在同一个 PDF 的两张发票，证据页码仍指向原始文件。

I02 保留每处历史同号引文。八位号码须比对双方同页的代码。完整组合相同会提示风险，组合相异会显示所排除的引文，前案代码有歧义、缺失或单据类型未经核准时提示证据不足。初审或独立复核点击通过时，在写入人工决定的同一事务内重查。新出现的相同标识或待核记录需要审阅，新出现的异代码票也留在签收回执，可查看双方原页。代码和号码均只取自已有证据。

## 遮盖号码与尾号

对于明确出现星号、遮盖方块、省略位、数字间连续 X 或只列尾号的票号，原件仍可逐字核对。即使申请与发票抄出相同的遮盖文字，I01、I02、T02 与 T03 也会保留缺口并指向原文。审计人员可以确认照片上可见的字符，再向提交人索取全号。单据同时列有多个候选且其中一个有明确遮盖时，该单据的标识归属待核。已核的完整发票仍可逐笔查看其检查结果。

## 银行流水号的原文完整性

B05 对照回单记载的字符和限定词。数字之间的连续 X、可见遮盖符，以及流水栏明确注明的尾号会保留为原页观察。同一原生文字页另列“交易流水号说明：仅显示后四位”时，底稿同时保留流水所在字段和说明所在行。收款账户的尾号说明只属于该账户，原样印出的完整流水保留前导零和字母大小写。

部分流水号会使 B04 至 B07 暂缓付款认定或精确比对。分期案 B08 保留已签收、同合同的历史回单。即使其中一份已由人工通过，只要其流水无法完整辨认，整项累计都待核。新查验同样核对旧版签收回单的原文。旧版若曾把可见的部分流水用于核对，或把该历史回单计入分期金额，审计员尝试通过时会得到对应原页，并可保留旧版重新审计。

## 付款底稿签收时的来源核验

出具 B06、B07、B08 时，引用的历史字段均须能对应到签收版留存的原件和页图。初审及独立复核通过前再读一次本案文件和实际引用的历史文件，校验 SHA-256，核对相关文字层及历史签收摘要。在填写人工决定的事务内，系统重新检查底稿、文件登记和文件状态。大文件的摘要计算在取得数据库写锁前完成。若某份回单原件遗失，审计员仍可查看留存的底稿和完好的页图，待原件恢复后再签收。

## 从前案重建应引用的依据

签收付款底稿时，系统按每项发现的用途，回到对应版本的历史签收原文，重新列出应引用的完整字段。同流水核对使用付款户名和流水号，同合同多笔全额付款核对使用两笔成功付款所据的合同、主体、账户、金额与日期，分期累计逐笔核对前案计入的流水、日期、金额与合同原件。初审和独立复核均校验签收时点、检索范围、计数、状态及所引字段。

从规则版本 2026.11.24.14 起，证据包可独立比对付款发现的文字说明、计入的金额及底稿总结。采购、差旅和付款案均根据逐项状态重算通过建议、是否需要人工核验和各类发现的数量。人工仍可填写验收意见，底稿保留签收时所据的 AI 建议。
