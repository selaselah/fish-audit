| `hero-enter`、`moment-none`，2 项 | 首屏使用本地 CSS 淡入和位移，支持减少动效。页内交互为切换原件和展开付款期次，工具按其动效脚本判断入场及展示段落。 |

文案检查另提示一次连续数字。100,000 元及 30%、60%、10% 均来自该笔合同，展开各期可以读到对应原文。全页使用墨绿标记入口和选择态，纸白展示单据，琥珀色标出需要核对的原文。品牌沿用已有的 Fish Audit，图标和细线底纹为本版绘制。[案例原文及摘要](../../3rd/showcase-provenance.md)

## 浏览器与真实流程

| 检查 | 结果 |
| --- | --- |
| 320、390、768、820、1024、1440 像素宽 | 本机与企业两种模式通过首页导航、键盘切换、三份原件摘要、登录或工作台入口及旧书签回归。 |
| 桌面和手机核图 | 桌面从验收疑点定位到原页框选的 8°C。手机可在同一条引文与原页间切换。台账数量与服务端同一检索范围的结果一致。 |
| 企业实际业务流程 | 使用隔离数据库与合成资料，实测员工提交、逐页解析、保存核图、在第 2 版底稿上签收退回、导出后复算。模型实际调用 7 次，17 项发现和 3 项计算可从该底稿核查。 |
| 服务端与可访问性 | 247 个服务端测试通过。axe-core 4.14.1 在首页、台账、上传、核图和登录页各检查桌面和手机，共 10 个状态，自动识别的违规项为 0。部分有底纹或覆盖层的文字对比度需人工判断。 |
| 本机页面性能 | 1440 和 390 宽各测 3 次。整页传输分别为 192.3 KiB 与 188.6 KiB，布局偏移中位数均为 0，失败请求为 0。工具提示页首和页尾共用的标识为即时加载，手机显示的核图截图和底纹使用了较高分辨率。 |

截图和复现命令见[页面与交互设计](README.md#复核与维护)。
