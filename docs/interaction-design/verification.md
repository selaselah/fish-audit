## 配色验收

桌面和手机在实际浏览器中读取前景、底色，按 sRGB 相对亮度计算对比度。首页三份原件的读数、当前文件页签、企业登录按钮、台账主按钮和定位引文的状态标签纳入浏览器回归。手机原件入口的点击范围、系统强制颜色模式下选中页签的双下划线也一并检查。[浏览器回归](../../frontend/tests/product.mjs) · [配色依据与 W3C 来源](../../3rd/interface-color.md)

| 文字所在位置 | 文字与底色对比度 |
| --- | --- |
| 首页「进入工作台」、台账「新建审计」、企业登录按钮的白字 | 6.65∶1 |
| 白底石墨色正文、白底次要说明 | 15.46∶1、5.77∶1 |
| 已相符、待核风险、已知问题的文字与各自淡底 | 6.60∶1、6.49∶1、6.23∶1 |
| 待复核任务状态标签的紫字与淡紫底 | 6.74∶1 |

axe-core 对图案背景和手机弹窗中的部分引文报告需要补查。取首页与企业登录页网格截图中的最深交点，以较浅的说明文字计算，分别为 6.40∶1、6.39∶1。另把手机核图窗口中待补查的 39 个文本元素逐一滚入视野，读取前景及其最近的不透明底色，最低为 5.77∶1。

## 浏览器与真实流程

| 检查 | 结果 |
| --- | --- |
| 320、390、768、820、1024、1440 像素宽 | 本机与企业两种模式通过首页导航、键盘切换、三份原件摘要、登录或工作台入口及旧书签回归。 |
| 桌面和手机核图 | 桌面从验收疑点定位到原页框选的 8°C。手机可在同一条引文与原页间切换。台账数量与服务端同一检索范围的结果一致。 |
| 企业实际业务流程 | 上一版交互验收使用隔离数据库与合成资料，实测员工提交、逐页解析、保存核图、在第 2 版底稿上签收退回、导出后复算。模型实际调用 7 次，17 项发现和 3 项计算可从该底稿核查。本轮沿用已有合成底稿复查引文和三期付款条件。 |
| 服务端与可访问性 | 配色版回归中 247 个服务端测试通过。axe-core 4.14.1 在首页、台账、上传、核图和登录页各检查桌面和手机，共 10 个状态，自动识别的违规项为 0。人工补查详见上表。 |
| 本机页面性能 | 1440 和 390 宽各测 3 次。整页传输分别为 145.1 KiB 与 141.0 KiB，布局偏移中位数均为 0，失败请求为 0。工具提示页首和页尾共用的标识为即时加载，手机显示的核图截图保留了放大阅读所需的分辨率。 |

截图和复现命令见[页面与交互设计](README.md#复核与维护)。
